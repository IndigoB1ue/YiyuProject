# 任务系统

任务系统现采用通用配置结构，配置操作、扩展边界与独立验收方式见 [通用任务系统](generic_quest_system.md)。本文说明玩家操作和现有清洗剂任务的兼容流程。正式 demo 仍只接入「制作清洗剂」，学院、礼堂沿用原有流程；学生委托仅放在独立测试场景中。

## 玩家操作

- 首次进入罗维宿舍自动接取并追踪任务；重复进入不会重新接取或覆盖手动取消追踪。
- 点击「任务 [J]」或按 J 打开任务日志，查看进行中／已完成任务、说明与目标，并追踪或取消追踪。
- 追踪栏在宿舍和地图悬浮于左上方、顶部按钮栏下方，采用半透明样式，默认收起。炼金界面隐藏追踪栏，保留右上角「任务 [J]」按钮和 J 快捷键查看任务日志。剧情期间也隐藏追踪栏，但仍可打开任务日志。
- 打开任务日志暂停游戏与对话；关闭时恢复原有暂停状态。任务、背包、设置与存档窗口共享暂停管理。
- 「跳过引导」仅关闭教学描边和提示，不发物品、不完成任务，也不取消任务。

## 任务推进

稳定任务 ID 为 `make_cleanser`，阶段 ID 为 `get_recipe`、`collect_materials`、`craft`。

1. 配方道具或既有配方解锁记录满足获取配方目标。
2. 素材按任务引用的实际 AlchemyRecipe 检查，重复物品槽合计数量，数量从 PlayerInventory 实时读取。推理配方只公开必需槽的信息。
3. 实际炼金成功并确认目标产物结果后完成任务；进入炼金场景、获得其他产物、仅持有清洗剂或尚未确认的结果都不完成。

完成的阶段保留记录，素材消耗后不会倒退；库存计数仍显示当前数量。房间入口和炼金制作继续进行真实库存检查，阶段记录不能替代检查。原先入口硬编码的清水×3已改为读取实际配方；目前配方为粉末×1、熏香草×1、清水×2。房间领取数量保持原配置。

任务完成与后续剧情完成分开处理。AlchemyStoryTrigger 转交真实炼金确认事件，QuestManager 完成任务并记录完成动作，QuestFlow 执行配置的 `request_story` 动作。只有正在播放的指定 timeline 发出 `CheckAndActiveStairs` 才记录剧情完成、返回宿舍并开放楼梯。外部终止、读档清理不视为完成。被中断的剧情允许下次正常进入炼金界面时重试，读档本身不从头重播。

## 文件与职责

| 文件 | 职责 |
| --- | --- |
| `data/quests/catalog.tres`、`make_cleanser.tres`、`story_after_cleanser.tres` | 正式任务目录、任务阶段与后续剧情配置 |
| `addons/quest_editor/` | Godot 顶部“任务配置”编辑面板 |
| `scripts/quest/quest_data.gd` 与相关 Resource | 任务、阶段、目标、条件、完成动作与剧情的定义 |
| `scripts/quest/quest_system.gd` | 接取、追踪、通用目标检查、阶段记录、动作收据、任务存档与通知 |
| `scripts/quest/quest_flow.gd`、`quest_delivery_service.gd` | 剧情正常完成判断、完成动作执行与指定目标的真实物品交付 |
| `scenes/ui/quest/quest_ui.tscn`、`themes/quest_theme.tres` | 任务日志和追踪面板的布局与外观 |
| `scripts/core/overlay_pause_manager.gd` | 多窗口共享暂停状态，最后一个窗口关闭后恢复 |
| `scripts/rovin_room/rovin_tutorial_controller.gd` | 将任务目标映射为宿舍交互点描边 |
| `scripts/alchemy/alchemy_story_trigger.gd` | 炼金结果确认与界面显示的兼容适配 |
| `scripts/core/demo_flow.gd` | 原试玩结束提示与返回主菜单，从 GameProgress 移出 |

目前支持持有物品、配方获取、配方素材、制作确认、交谈、交付、剧情完成和业务事实目标。任务按阶段顺序推进，每个阶段可以要求全部目标或任一目标达成；学生支线用学生 ID、前置条件和后续任务动作组合。新增这些类型的任务只需要配置 Resource 并绑定相应交互入口；全新玩法事件才需要新增适配器和表单支持。

## 存读档兼容

GameSaveData 的 `quests` 字段保存已接任务、阶段／目标记录、事件收据、完成动作、追踪和收起状态；`quest_flow` 保存剧情播放身份和完成记录。整个存档格式版本继续为 1，任务子结构版本为 2，旧文件缺少相应字段时迁移。首次接取、重新选择追踪和新游戏默认收起；读档保留玩家已保存的展开／收起选择，旧档缺少该选择时默认收起。

- 旧档已开始或完成清洗剂后续剧情，视为已确认制作，迁移为已完成任务。
- 仅教程完成／跳过或库存中有清洗剂，不推断制作完成。
- 旧档位于宿舍／炼金场景，或有相关解锁／领取证据时初始化已接任务，再依据恢复的库存与解锁记录检查阶段。
- 所有子系统通过校验后才更改游戏状态；恢复过程中不重复接取、发奖励、发送任务完成事件或从头启动剧情。
- 新游戏清空任务和追踪记录，将追踪栏恢复为默认收起，保留玩家设置。

## 验证

在 Godot 4.7.2 中使用 `--headless --path . --script res://tests/<名称>.gd` 运行：

- `quest_system_test`：状态推进、锁存、公开信息、旧档迁移、任务存读档、坏存档拒绝和新游戏。
- `quest_ui_test`：任务日志、真实输入、追踪、窗口暂停、对话恢复与较小窗口布局。
- `quest_story_test`：真实炼金确认、剧情重试、匹配 timeline 结尾、中断与恢复。
- `generic_quest_test`、`quest_flow_test`：全部／任一阶段、扩展适配、事件与交付隔离、历史策略、动作幂等及失败重试。
- `quest_editor_test`、`quest_editor_plugin_smoke`：配置表单、保存与引用、撤销重做、公开预览，以及真实编辑器插件启用。
- `quest_sandbox_test`：独立学生委托完整流程与中途存读档，核对正式游戏进度未变更。
- `rovin_tutorial_test`、`rovin_tutorial_skip_test`、`rovin_entry_test`、`rovin_alchemy_test`：宿舍交互、库存检查和教学整合。
- 原存档、背包、设置、炼金及楼梯／学院／礼堂流程继续回归。

测试存档建议使用独立的 APPDATA 目录，避免覆盖实际游玩存档。
