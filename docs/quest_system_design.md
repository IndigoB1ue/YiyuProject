2026-10-25 更新：通用任务数据、顺序阶段与并行目标、专用配置面板、交谈／交付／剧情适配和学生任务链现已实现，详见 [通用任务系统与配置](generic_quest_system.md)。新增学生委托仅用于独立测试场景验收，正式 demo 的原有路线保持不变。当前追踪栏规则以实现文档为准：宿舍和地图左上悬浮、默认收起；炼金界面隐藏追踪栏并保留任务按钮。

本文件记录任务系统、玩家任务界面及现有试玩内容的整合方案。已有功能和规则参见 [炼金系统](alchemy.md)、[学院地图](academy_map.md)、[存读档](save_load.md)、[昼夜设计](day_night_design.md) 和 [叙事推理炼金设计](alchemy_experiment_design.md)。

## 一、整体方向

试玩版与完整版共用背包、物品、炼金、剧情播放、场景切换、设置和存读档等基础系统。试玩内容单独组织，配置自己的任务、剧情、起点和结束位置。

主线、支线以任务目标及任务状态表达推进关系；剧情播放、场景开放和场景切换根据任务或事件条件执行。
以后增加章节和学生支线时，继续复用基础系统，分别增加任务内容。多条任务可以拥有各自的进度，不以一个全局步骤代表整个游戏。

当前只需先用一条任务验证闭环。试玩的最终结束位置仍需按剧本确定，不在本次讨论中指定。

## 三、“制作清洗剂”任务

### 目标结构

任务可以按以下阶段组织；具体阶段 ID、显示文本和数据字段在实现时统一：

| 阶段 | 玩家目标 | 检查依据 |
| --- | --- | --- |
| 获取配方 | 在宿舍中找到清洗剂配方 | 指定配方道具及现有解锁记录 |
| 准备素材 | 收集当前配方要求的必需素材 | 实际背包数量和配方需求 |
| 制作清洗剂 | 前往炼金区域，制作并确认获得目标产物 | 成功的目标产物结果确认事件 |

“前往炼金区域”可以作为制作阶段的当前目标提示。仅进入炼金场景不算完成任务，追踪需要继续到目标产物的结果确认。

任务不要求玩家严格按界面提示的顺序寻找物品。先取得素材、后取得配方时，应识别已有进度并进入适当阶段。

### 素材目标与数据来源

任务目标读取实际配方中的公开必需素材需求，同一种物品跨槽使用时合计数量。背包数量继续从 InventorySystem 查询。
不在任务脚本或 UI 中另外写一份库存，也不固定沿用讨论时的素材数量示例。

对于后续推理配方，任务显示遵循炼金的公开信息规则：隐藏答案不能通过任务说明、计数或高亮泄露。

需要区分两种进度：

- **当前条件**：现在是否持有足够素材，由背包实时判断。
- **完成记录**：已经完成的任务阶段、制作确认等事实，由任务进度保存。

已完成的阶段不会因为后续炼金消耗素材而倒退。若进入下一阶段前素材被其他系统消耗，实际炼金仍进行库存检查，并给出缺少素材的反馈；任务记录不能代替炼金验证。

### 完成与剧情的时序

```text
AlchemySystem 验证并完成炼金
→ 产物加入背包
→ 显示炼金结果
→ 玩家确认获得目标产物
→ “制作清洗剂”任务完成
→ 衔接已配置的后续 timeline
→ 对应剧情完成
→ 返回宿舍并开放楼梯
```

任务完成不需要等待后续 timeline 结束。楼梯开放仍以对应剧情完成为条件。

验证失败、得到其他产物、只打开结果窗口但尚未确认，都不能作为本任务的完成事件。
物品数量变化用于更新收集目标；制作目标使用成功结果确认事件，避免把其他来源获得的同名物品直接当作本次制作确认。

任务完成、后续剧情启动及剧情完成应各自只处理一次。迁移时要协调现有 AlchemyStoryTrigger，明确每个动作的执行入口，避免任务系统和旧控制器重复播放同一剧情。
剧情完成需对应指定 timeline；读档、切换流程或退出导致的对话终止不能被误判为正常完成。

## 四、玩家可见的界面

### 任务列表窗口

用于查看已接任务、已完成任务、任务说明和目标进度，并选择当前追踪的任务。
未追踪的任务仍然可以正常推进。

第一版实际接入一条主线任务。主线、支线的分类和更多任务内容可以后续扩充，窗口结构保留这种扩展空间。

任务入口按钮、快捷键、窗口尺寸和具体排版尚未确定，实施前结合现有全局 UI 布局细化。

### 当前目标追踪面板

复用 RovinRoom 左下角旧引导面板的合适部分，整合为显示一项追踪任务的小面板：

```text
[主线] 制作清洗剂

当前目标：收集炼金素材
所需素材及数量按当前配方与背包显示

[任务列表]  [收起]
```

完整任务列表与追踪面板读取同一份任务状态。目标变化后两处同步更新。
进入炼金场景后仍可继续追踪，不再因离开宿舍而结束任务提示。

任务 UI 继续采用可在 Godot 编辑器中调整的场景与 Theme。具体入口位置及在地图、炼金、对话等界面的布局在实施时检查，避免遮挡已有操作。

### 教学辅助与任务分别管理

| 玩家操作或状态 | 效果 |
| --- | --- |
| 收起追踪面板／取消追踪 | 调整目标展示，任务保留并继续推进 |
| 跳过引导 | 关闭教学提示和引导用的目标描边，不完成或放弃任务，不发放物品 |
| 完成任务 | 由实际目标条件及完成事件决定 |
| 试玩结束 | 由试玩内容的结束节点决定，不等同于本任务完成 |

旧引导包含标题、说明、素材计数及目标高亮，可以复用这些展示能力。任务目标的判断迁入任务系统，房间侧负责把目标对应到书柜、家具和炼金区域等实际交互点。
“教程已结束／已跳过”与“任务已完成”保持不同含义。

### 对话期间打开任务列表

允许在 timeline 播放期间打开任务列表。
打开时记录原有播放与暂停状态，暂停对话；关闭后恢复打开前的状态，避免强行恢复本来已经暂停的对话。

与现有背包、设置等窗口统一处理输入和窗口层级。多窗口叠加时，关闭其中一个窗口不能提前解除其他窗口需要的暂停；打开或关闭列表的输入也不能顺带推进台词。

追踪面板在对话期间显示还是自动隐藏，尚未单独确定，后续结合剧情界面排版处理。

## 五、数据与职责建议

以下为实现方向，尚未新增对应代码；命名和文件划分可以按实际需要调整。

| 部分 | 职责 |
| --- | --- |
| QuestData 等任务 Resource | 配置任务 ID、名称、说明、接取条件、阶段、目标和完成后的动作 |
| QuestSystem | 管理接取、目标检查、阶段推进、完成与任务存档数据，发出变化通知 |
| GameProgress | 保留全局进度入口，任务相关记录由任务系统管理；不继续逐任务添加专属布尔变量 |
| InventorySystem / AlchemySystem | 查询、验证和修改物品，报告需要的业务事件 |
| Dialogic 接入部分 | 播放指定剧情并报告可识别的开始、完成事件 |
| SceneManager | 执行场景切换，报告成功或失败 |
| 场景交互控制器 | 执行房间或地图交互，将任务目标关联到实际交互点 |
| 任务列表与追踪 UI | 显示任务和进度，接收追踪、收起等操作 |

同一任务的推进依据统一由任务状态提供，避免再维护另一份独立的主线步骤。
第一版可以用简单 Resource 和稳定步骤 ID 配置任务，先接入确实需要的物品目标、炼金结果确认与现有剧情衔接。

任务系统复用现有奖励与物品接口，保留当前房间的一次性领取和失败重试规则。若以后增加任务额外奖励，再明确奖励配置和领取记录，确保不会重复发放。
节点式任务编辑器、复杂失败／放弃规则和大规模任务平台不属于本次确认的第一版范围。

## 六、存读档与迁移

任务存档需要能够恢复已接任务、各任务阶段及已完成记录；追踪哪项任务也应随进度恢复。
背包、配方解锁、领取记录和 Dialogic 播放位置继续复用现有存档能力。

实现时区分“首次进入阶段”和“读档恢复阶段”：恢复进度与界面不应重新发放奖励、重复接取任务或从头启动剧情。
读档后依据任务状态重新显示目标和可互动提示，不保存场景节点引用。

现有 GameProgress 的教程和清洗剂剧情标记需要逐项迁移或兼容。不能把“已经进入炼金场景／跳过教程”直接解释成“制作清洗剂任务完成”。
旧存档的任务状态缺失时如何初始化，需要结合既有完成标记处理；具体兼容规则在实施时确认，不能仅因背包存在目标物品就推断玩家已确认制作结果。

## 七、当前项目接入核对项

以下记录现有实现与未来迁移有关的事实，本次均不修改：

- `scripts/core/game_progress.gd` 当前混合了配方解锁、领取记录、教程／剧情标记及确认弹窗等职责。任务接入时，需要把弹窗与固定返回主菜单等操作移到对应界面或内容流程。
- `scripts/rovin_room/rovin_tutorial_controller.gd` 当前在进入炼金场景后结束教程；整合任务后，这不能作为制作任务的完成点。
- 房间的地图按钮当前依赖教程完成或跳过状态。迁移时应核对这些依赖，保留正常导航，避免教程显示开关意外改变任务或剧情条件。
- `scripts/alchemy/alchemy_story_trigger.gd` 当前负责结果确认后的剧情与返回房间，需要与任务完成事件协调。
- 当前楼梯进入学院地图；礼堂入口播放后续剧情。已有路线继续保留，后续再增加对应任务定义。
- 2026-10-24读取到的 `data/recipes/clear_potion.tres` 需求为清洗剂粉末×1、Herb×1、清水×2；旧房间入口仍存在配方道具与清水×3的检查。任务目标以实际配方为数据来源，正式接入前需要核对入口条件与配方的关系，不直接沿用讨论时“粉末×1、清水×3”的示例，也不在本次文档工作中自行修改规则。

## 八、后续实施顺序与验收

用户决定开始实现后，建议按以下顺序推进：

1. 明确旧进度兼容和现有交互接入点，整理 GameProgress 的状态与操作职责。
2. 建立最小任务数据及运行逻辑，只配置“制作清洗剂”。
3. 接入房间收集、跨场景追踪与炼金结果确认；协调现有后续剧情。
4. 将旧引导面板整合为追踪面板，增加完整任务列表窗口，接入对话暂停与恢复。
5. 接入存读档并完成回归，再扩充学院／礼堂任务链及试玩结束节点。

第一版至少验证：

- 首次进入宿舍自动接取，重复进入不重复接取。
- 提前收集或自由顺序收集能正确识别，任务 UI 与实际背包一致。
- 跳过引导、收起面板或取消追踪后，任务仍保留并继续推进。
- 进入炼金场景不提前完成任务；验证失败、其他产物或尚未确认的结果不完成任务。
- 确认目标产物后完成一次任务，后续剧情只启动一次；剧情完成后再开放楼梯。
- 素材正常消耗，已完成阶段保持完成；任务不会绕过背包或炼金验证。
- 打开任务列表不会误推进台词，关闭后正确恢复原有暂停状态。
- 读档恢复任务、追踪与剧情位置，避免重复奖励、重复剧情或错误开放入口。
- 现有炼金扩展、配方解锁、地图导航和试玩剧情仍正常运行。

## 九、留待实施时细化

- 任务列表入口、快捷键、样式及追踪面板在不同界面中的具体位置。
- 阶段 ID、正式任务文案、旧存档兼容方式，以及当前房间入口与配方需求的核对。
- 后续学院、礼堂和学生支线的任务拆分、接取条件及完成点。
- 与白天／黑夜的具体条件接入，以及试玩最终结束位置。

以上不影响已确认的第一版方向。任何会改变玩法或剧情条件的未决项，在实现前向用户确认。
